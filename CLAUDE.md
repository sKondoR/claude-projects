# CLAUDE.md

Claude Projects — десктопное приложение (Windows) с доской задач проектов. Оно заменяет прежние HTML-доски задач в проектах.
Решения и их причины — [docs/decisions.md](docs/decisions.md).

## Что делает

- Вкладки — проекты. «+» добавляет папку проекта, «×» убирает её из приложения, файлы при этом остаются.
- При добавлении приложение создаёт недостающие группы `docs/issues/{issues,security-issues,architecture-issues,other-issues,backlog}.md`.
- Приложение держит в каждом проекте управляемые файлы из эталона [rules/](rules/):
  - блок `issues-rules` в `CLAUDE-ISSUES.md`;
  - блок `issues-pointer` в `CLAUDE.md` с импортами `@CLAUDE-ISSUES.md` и `@CLAUDE-ISSUES-LOCAL.md`;
  - скрипт отметок `docs/issues/issues-status.mjs`;
  - хук Claude Code `docs/issues/issues-hook.mjs` и его записи в `.claude/settings.json` (`src/core/hooks.ts`): отметки simplify и review;
  - проверка `docs/issues/issues-pre-push.mjs` и git-хук `.git/hooks/pre-push`, который её запускает: push в основную ветку отменяется, если коммит называет задачу, а она ещё открыта. Чужой `pre-push` и `core.hooksPath` приложение не трогает и пишет об этом на вкладке. Если папка проекта не в git, хук ставится в репозитории подпапок до второго уровня, а проверка читает задачи с диска. Репозитория нет — предупреждение на вкладке.
- Правила проекта лежат в `CLAUDE-ISSUES-LOCAL.md`. Если файла нет, приложение создаёт его из `rules/local.md` и больше не меняет.
- Эталон синхронизируется при запуске и при изменении файлов в папке эталона. Путь к папке хранится в настройках, по умолчанию — `rules/` этого репозитория.
- Доска следит за `docs/issues`, `docs/resolved`, `CLAUDE.md`, `CLAUDE-ISSUES.md` проекта и его git worktree.
- Закрытые задачи старого формата `- [x] **У4 · …**` в `docs/resolved` тоже занимают номер: повтор номера — предупреждение на карточке.
- Раз в 5 минут приложение спрашивает GitHub через `gh` (`src/main/github.ts`): отметку «PR» влитого или закрытого PR снимает, о worktree с влитой веткой пишет на вкладке. Кнопка «На свежий main» в этой строке забирает основную ветку из origin и делает `git switch --detach origin/<ветка>`: основная ветка открыта в папке проекта, а git не открывает одну ветку в двух worktree. Если в worktree запущена сессия Claude Code, кнопка спрашивает подтверждение. Без `gh` проверки нет.
- Перенос (перетаскивание) и «Сделано» приложение пишет в `.md` само (`src/core/edit.ts`).
- «В работу» в раскрытой карточке открывает вкладку Windows Terminal в папке проекта и запускает `claude` с номером и сутью задачи (`src/core/launch.ts`). Кнопка неактивна, если у задачи есть вопросы или она ждёт этапа.
- Поиск на вкладке ищет в номере, заголовке, разделе, тексте и вопросах (`src/core/search.ts`). Ctrl+F ставит курсор в поле, Esc и смена вкладки очищают его.
- ⚠ на вкладке — абзацы общих правил, которые повторяются в корневом `CLAUDE.md` проекта; блок, вставленный приложением, не в счёт (`src/core/overlap.ts`). Из пары открывается и файл проекта, и `issues-rules.md` эталона.
- Круг на вкладке — запущенные сессии Claude Code в проекте и его worktree: зелёный с числом сессий, серый — сессий нет. Приложение читает `~/.claude/sessions/<pid>.json` (формат не документирован) и проверяет, что процесс жив (`src/core/sessions.ts`, `src/main/sessions.ts`).
- Часы в правом верхнем углу открывают справа панель учёта времени: по дням время работы и задачи дня. Время работы — Claude работает или ждёт вас не дольше 5 мин; по часам, параллельные сессии считаются один раз (`src/core/timelog.ts`, `src/main/timelog.ts`). Приложение читает транскрипты сессий проекта и его worktree `~/.claude/projects/<папка>/*.jsonl` (формат не документирован). Задача сессии — из отметки `issues-status.mjs <номер> work` или запроса кнопки «В работу», иначе название сессии от Claude. Разбор транскриптов хранится в `%APPDATA%\Claude Projects\timelog\`: Claude Code удаляет транскрипты старше 30 дней, а прошлые дни остаются. Приложение не удаляет записи кеша и не перезаписывает нечитаемый файл кеша; удаление приложения папку не трогает.
- Кнопка графа в правом верхнем углу показывает задачи вкладки графом зависимостей (`src/core/graph.ts`). Столбцы — шаги слева направо: в первом задачи без открытых зависимостей, в шаге N — задачи, чья самая поздняя зависимость в шаге N−1. Задач с вопросами владельцу, задач бэклога и задач после них в графе нет. Линию через промежуточную задачу граф не рисует. Фильтры и поиск делают остальные карточки бледнее, фильтра «Владелец» в графе нет, наведение выделяет цепочку задачи.
- Меню в правом верхнем углу: тема светлая или тёмная. Тёмная — по дизайну прежней HTML-доски без неонового свечения. Выбор хранится в настройках; до выбора тема как в Windows (`nativeTheme`).
- Окно закрывается в трей. Установленное приложение включает автозапуск с Windows один раз.

## Устройство

```
src/core      чистая логика без Electron: разбор задач, перенос, закрытие, блоки правил, пересечения, markdown, ссылки, worktree  ← тесты Vitest
src/main      основной процесс: файлы проекта (project.ts), слежение (watch.ts), настройки, окно, трей, IPC
src/preload   window.api для окна
src/renderer  Svelte 5: вкладки, столбцы, карточки
src/shared    типы обмена между процессами
rules         эталон правил, ссылки и скрипта отметок
```

Логику с текстом файлов пиши в `src/core` и покрывай тестами. `src/main` только читает и пишет файлы.

## Команды

```
pnpm dev      запуск с горячей перезагрузкой
pnpm test     тесты core и файловых операций (временные папки)
pnpm check    svelte-check и TypeScript
pnpm dist     установщик NSIS в dist/
```

Проверить правку в окне (скриншоты, клики) — навык `/run-claude-projects`: драйвер запускает сборку с временными настройками и проектом-примером.

Настройки приложения: `%APPDATA%\Claude Projects\settings.json`.
