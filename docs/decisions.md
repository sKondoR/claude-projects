# Решения по приложению-трекеру задач

Десктопное приложение заменяет HTML-доски задач в двух проектах: проект А и проект Б.
Вкладки — проекты. Кнопка «+» добавляет проект через выбор папки. В проекте приложение создаёт файлы задач и дописывает правила в `CLAUDE.md`. Приложение следит за файлами и показывает задачи в сворачиваемых вертикальных столбцах.

Журнал решений после интервью (grilling). Статусы: **открыт** — ждёт ответа, **принят** — решение согласовано.

## Факты (2026-11-19)

### Текущие доски
- Проект А: сервер доски на Node `http` без зависимостей и страница на vanilla JS, порт 3201. Страница опрашивает сервер раз в 30 с, слежения за файлами нет.
- Проект Б: сервер доски, порт 3200, `pnpm issues`. Читает задачи из `origin/main` (git fetch раз в минуту) и из несмёрженных веток и worktree.
- Других проектов с `docs/issues/` нет.

### Файлы
- Оба проекта: `docs/issues/<группа>.md`, один файл на группу. Закрытые задачи — `docs/resolved/<группа>-DONE.md`.
- Проект А: `issues.md`, `security-issues.md`, `backlog.md`.
- Проект Б: `issues.md`, `security-issues.md`, `architecture-issues.md`, `issues-e2e.md`, `legal.md`, `backlog.md`. Файла `other-issues.md` нет.
- Правила — `docs/issues/CLAUDE.md` в каждом проекте (111 строк в проекте А, 14 КБ в проекте Б). Корневой `CLAUDE.md` ссылается на него короткой секцией.
- Боковые файлы: `docs/issues/status.json` (метки сессий), `docs/issues/moves.json` (переносы с доски, только в проекте А).

### Формат записи
- `## ` — раздел, `### <ID> · <заголовок>` — карточка.
- Строка полей через ` · `: **Приоритет**, **Трудность**, **Риск** (0/1/2, обязателен), **Зависит от**, **Ждёт этапа**, флаг **Уточнить у владельца** (в проекте Б — «заказчика»), **Найдено**.
- `**Вопрос владельцу:**` и варианты `- …` (суффикс ` (рекомендуем)`).
- Номер: буква области + число. Буквы свои в каждом проекте.
- Группа архитектуры в проекте Б имеет свой формат: **Файлы:**, **Проблема.**, **Решение.**, **Выигрыш.**

### Действия на доске
- Метки `work / simplify / review / pr` ставит `issues-status.mjs` через `POST /api/status`, хранятся в `status.json`. В проекте Б метки simplify/review ставит свой хук.
- Перенос карточки мышью пишет `moves.json`. Блок в `.md` переносит Claude.
- UI: столбцы `grid-auto-flow: column`, свёрнутый столбец — 44 px. Фильтры: трудность, этап, владелец.

### Инструменты на машине
- Есть: Node 24.22, pnpm 12.16, Python 3.12, WebView2 Runtime 157.
- Нет: Rust, cargo, MSVC / VS Build Tools, .NET SDK, Go.

## Отличия реализации от решений (2026-11-19)

- Q21: логика лежит в папке `src/core`, а не в отдельном пакете `packages/core`. Один пакет проще собрать в установщик: electron-builder не тянет пакеты рабочего пространства. Граница та же: `src/core` не импортирует Electron и покрыт тестами.
- Q15: шрифты системные (Segoe UI, Georgia) вместо Google Fonts: приложение работает без сети.
- Q15: полоса «переносы ждут Claude» и `moves.json` убраны: приложение переносит задачи само (Q10).
- Q12: скрипт `issues-status.mjs` отказывает, если задачи нет в `docs/issues` рядом с ним, и если адрес PR не `https://github.com/…`, как прежний сервер доски.
- Q14: в worktree у каждой копии свой `status.json`; доска берёт самую позднюю отметку задачи из всех копий.
- Q14: worktree без ветки (rebase, detached HEAD) тоже виден: вместо имени ветки — начало хеша коммита. Проект может быть подпапкой репозитория: в каждой копии берётся та же подпапка.
- Q19d: по решению пользователя пересечения ищутся только в собственном тексте корневого `CLAUDE.md` — без блока-ссылки приложения и подключённых через неё правил. Правила проекта (`CLAUDE-ISSUES-LOCAL.md`) и старый `docs/issues/CLAUDE.md` не сравниваются.
- Q19c: по решению пользователя правила проекта лежат в отдельном `CLAUDE-ISSUES-LOCAL.md` в корне, а не в разделе «Правила проекта» под блоком `CLAUDE-ISSUES.md`. Приложение создаёт файл из `rules/local.md`, только если его нет, и подключает его в `CLAUDE.md` вторым импортом. `CLAUDE-ISSUES.md` теперь целиком файл приложения; раздел в уже добавленных проектах приложение не трогает — его переносят вручную.
- Q2: кроме перетаскивания, в раскрытой карточке есть список «Перенести в»: перенос с клавиатуры и в узком окне, где перетаскивать неудобно.
- Q15: ссылки на файлы в тексте карточки работают. Документы и картинки открывает программа Windows, папки — Проводник. Остальные файлы (`.bat`, `.exe`, `.js`, …) Проводник только показывает, приложение их не запускает. Ссылки за пределы проекта не работают.
- Q17: хеш в маркере проверяется. Текст блока не совпал с хешем — блок правили руками: приложение блок не перезаписывает и показывает ошибку на вкладке. Маркер без хеша проверить нельзя: такой блок приложение обновляет. Скрипт `issues-status.mjs` — не блок, хеша у него нет: приложение всегда пишет его из эталона, правки — только в эталоне.
- Q17: копии `rules/` в установщике нет: она устаревала бы и молча писала старые правила в проекты. Папки эталона нет — на вкладках ошибка эталона, путь в настройках остаётся, приложение проверяет папку раз в минуту.
